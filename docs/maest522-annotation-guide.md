# Последовательная разметка датасета MAEST 522

Инструмент собирает локальный multilabel-датасет для трёх новых выходов MAEST
в фиксированном публичном порядке:

```text
519  Electronic---Minimal-Deep-Tech
520  Electronic---Microhouse
521  Electronic---RoMinimal
```

Основной режим — один активный жанр за раз. Можно полностью закончить
`Minimal-Deep-Tech`, затем перейти к `Microhouse` и `RoMinimal`. Интерфейс не
переключает жанр автоматически. Тот же трек можно независимо оценить в очереди
другого жанра.

## 1. Установка и запуск

Из корня репозитория:

```powershell
& '.\.venv\Scripts\python.exe' -m pip install -r '.\requirements-annotation.txt'
& '.\.venv\Scripts\python.exe' '.\tools\annotation_ui.py' `
  --db '.\annotation-projects\maest522\annotations.db'
```

Откройте [http://127.0.0.1:8522](http://127.0.0.1:8522). Сервер по умолчанию
доступен только локально. База содержит абсолютные пути к фонотеке, поэтому не
публикуйте её и не открывайте UI в сеть без отдельной защиты.

Для финальных fingerprints желательно явно передать Chromaprint и FFmpeg:

```powershell
& '.\.venv\Scripts\python.exe' '.\tools\annotation_ui.py' `
  --db '.\annotation-projects\maest522\annotations.db' `
  --fpcalc 'C:\Utils\tools\fpcalc.exe' `
  --ffmpeg 'C:\Utils\tools\ffmpeg.exe'
```

## 2. Миграция старого проекта v1

Обычный запуск намеренно не изменяет старую базу. Для проекта v1 с двумя
доверенными источниками `100 да + 100 нет` сначала остановите UI и выполните
явную backup-first миграцию. Пример для проекта 1 и source IDs 1/2:

```powershell
& '.\.venv\Scripts\python.exe' -m tools.maest522.migrate_annotation_db `
  --db '.\annotation-projects\maest522\annotations.db' `
  --backup '.\annotation-projects\backups\annotations-v1-pre-migration.sqlite' `
  --project-id 1 `
  --positive-source-id 1 `
  --negative-source-id 2
```

Мигратор принимает только проверяемый старый контракт: оба источника относятся
к прежней метке `Electronic---DeepTech-Minimal`, содержат ровно по 100
непересекающихся существующих файлов и не имеют старых очередей. При любом
несоответствии исходная база остаётся без изменений.

## 3. Основной цикл одного жанра

1. Создайте или откройте единый проект.
2. Выберите активный жанр.
3. Оставьте цели `1000 да + 1000 нет` или задайте другие значения.
4. В своём приложении кандидатов подготовьте два проверенных плейлиста:
   положительный и hard-negative.
5. Импортируйте их через `Preflight`, затем `Commit`.
6. Добавляйте следующие плейлисты, пока обе цели жанра не выполнены.
7. Вручную переключите активный жанр и повторите цикл.

Цели мягкие: их можно увеличить или уменьшить до фиксации split. Уменьшение
ничего не удаляет, превышение цели разрешено. `Не уверен` хранится в журнале,
но не засчитывается ни в `да`, ни в `нет`.

## 4. Доверенный M3U/M3U8

Поле принимает локальный путь на машине, где запущен сервер, например:

```text
C:\projects\minimal-deep-tech-positive.m3u
```

Внутри плейлиста допустимы абсолютные пути и пути относительно папки самого
M3U. Комментарии `#EXTM3U`/`#EXTINF` игнорируются. Удалённые URL запрещены.

`Проверить` выполняет read-only preflight:

- разрешает и проверяет каждый путь;
- вычисляет SHA-256 плейлиста и аудиофайлов;
- находит отсутствующие, неподдерживаемые и повторяющиеся записи;
- блокирует противоположную уже подтверждённую метку.

`Подтвердить импорт` становится доступен только после чистого preflight.
Commit повторяет проверку, сверяет digest и записывает всю партию одной
транзакцией. Повтор того же плейлиста с той же меткой идемпотентен. Изменённый
плейлист требует нового preflight. Противоречие блокирует всю партию —
частичного импорта нет.

Положительный M3U означает `positive`. Отрицательный плейлист должен содержать
полезные hard negatives: близкие Microhouse/RoMinimal/Minimal Techno и другие
пограничные треки, а не случайный далёкий материал.

## 5. Дополнительная ручная очередь

Раздел `Дополнительно` нужен только для кандидатов, которые ещё требуется
прослушать. Импортируйте папку или M3U как candidates и создайте очередь строго
для активного жанра. На карточке доступны:

| Клавиша | Действие |
|---|---|
| `Space` | play/pause |
| `P` | да |
| `N` | нет |
| `U` | не уверен / пропустить |
| `J`, `K`, `L` | перейти к 20%, 50%, 80% трека |
| `Enter` | сохранить и перейти дальше |
| `Backspace` | предыдущая карточка |

Решение записывается в тот же append-only confirmed-label journal, что и
доверенные M3U. Предсказания teacher/student не показываются.

## 6. Финализация без leakage

Кнопки финализации блокируются, пока не выполнены `+/-` цели всех трёх жанров.
После этого порядок строгий:

1. `Fingerprints` — только supervised-треки с `positive/negative`.
2. `Зафиксировать split 70/15/15` — один раз для объединённого датасета.
3. Проверить `audit_clean=true`.
4. `Экспортировать manifest`.

Exact-копии, одинаковые acoustic fingerprints, один release и один
нормализованный artist объединяются в group. Весь group попадает только в один
из `train`, `val`, `test`. Стратификация использует шесть сигналов: `+/-` для
каждого нового класса. Экспорт блокируется, если в каком-либо split нет хотя бы
одного положительного или отрицательного примера для любого класса.

После freeze нельзя импортировать новые партии, исправлять решения или менять
цели. Если состав датасета должен измениться, восстановите backup либо создайте
новый проект и сформируйте split заново; не перемешивайте уже открытый test.

## 7. Manifest и резервная копия

UI создаёт:

```text
<папка-базы>/exports/<project_id>/training.jsonl
<папка-базы>/exports/<project_id>/dataset_summary.json
```

Portable manifest не содержит локальных audio/M3U paths. Он хранит SHA-256
track ID, group ID, split, offsets окон, все три состояния и `label_mask`.
`positive/negative` имеют mask 1; `uncertain/unreviewed` — mask 0 и не входят в
classification loss.

Перед ручной резервной копией остановите UI:

```powershell
$backupDir = '.\annotation-projects\backups'
[System.IO.Directory]::CreateDirectory($backupDir) | Out-Null
Copy-Item -LiteralPath '.\annotation-projects\maest522\annotations.db' `
  -Destination (Join-Path $backupDir 'annotations-backup.sqlite')
```

Исходные аудиофайлы инструмент не изменяет. Preview cache рядом с базой не
входит в training manifest.
